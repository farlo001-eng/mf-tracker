## Current State (2026-06-04)

The property detail is now a focused modal overlay rendered via `createPortal` into
`document.body`, completely decoupled from the scrollable table grid.

### How the modal works
- Clicking the expand chevron in any table row sets `expanded` in `Tracker`, which
  passes `open={true}` down to that `PropertyRow`.
- `PropertyRow` renders a `createPortal(...)` targeting `document.body` when `open`
  is true. While the detail API call is in flight it shows a "Loading…" state; once
  resolved it renders the full detail body.
- Clicking the backdrop (`modal-bg`) or the X button calls `onToggle` to close.
- Pressing Escape also closes via a `window.addEventListener("keydown")` effect
  that is torn down when the row closes.
- The table row itself no longer has a second `<tr>` sibling; the `<>` fragment now
  contains only the data row.

### Layout structure
```
.modal-bg (fixed overlay, z-index 50)
  └── .card.detail-modal (720px, max-height 88vh, flex column)
        ├── .detail-head (sticky header — property name, address, X button)
        └── .detail-body (scrollable, flex column, gap 14)
              ├── Editable fields (owner, phone, email)
              ├── Status / follow-up / quick-date pills
              ├── NotesBox
              ├── Touch logger
              ├── Touch history
              └── All property data (expandable)
```

### Column reordering
Columns can be dragged to reorder by dragging a header cell. A `dragCol` ref holds the
field key of the column being dragged; `moveCol(from, to)` splices `cols` state in place
and persists to localStorage via the existing `useEffect`. The `:active` CSS rule gives
visual feedback (grabbing cursor + rust color) while dragging.
