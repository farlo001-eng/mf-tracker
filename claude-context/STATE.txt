## Current State (2026-06-04)

Four improvements landed on top of the spreadsheet table:

1. **Notes field** — `properties.notes TEXT` column added via idempotent migration.
   Surfaced as a `NotesBox` textarea in the property detail row (saves on blur).

2. **Column visibility picker** — "Columns" button in the toolbar opens a floating
   checklist of all core + extra keys. Selection is persisted in `localStorage` under
   `mf_cols`. `visibleCols` (computed from `cols.map(colDesc)`) is passed down as a
   prop to `PropertyRow`, replacing the old static `TABLE_COLS` constant.

3. **Follow-up date fix** — `next_follow_up` is now formatted as `YYYY-MM-DD` in both
   the list query (`to_char(p.next_follow_up,'YYYY-MM-DD')`) and the detail query,
   so date inputs always receive a clean ISO string regardless of the Postgres client
   timezone setting.

4. **Scrollable table** — `.tbl-wrap` now has `max-height: 68vh` and `overflow: auto`
   so the sticky header stays visible while scrolling long lists.

### Architecture notes
- `CORE_COLS` object maps column key → `{label, w, type?, num?}`.
- `colDesc(key)` converts a key string to a column descriptor, treating unknown keys
  as `extra: true` (read from `p.extra[key]`).
- `extraKeys` is derived via `useMemo` from the current `props` array — populated once
  properties with `extra` data are loaded.
- "All property data" values are now `<input>` fields that PATCH on blur via
  `{ extra: { [k]: newValue } }` (additive merge).

### Next step
